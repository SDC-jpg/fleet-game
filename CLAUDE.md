# Project notes for Claude

## About the user
- New to coding and to AI-assisted development. This is a learning project to try making games with Claude.
- Explain what you're doing in plain language. Keep changes small.

## Goal and stack
- A simple browser game the user can play and keep improving.
- TypeScript + React, built with Vite.
- No game engine. Write a small engine of our own, made just for this game.

## Workflow
1. Build a quick, rough playable prototype first, before any design doc.
2. The user plays it and sends batches of notes. Implement them.
3. Once the design settles, write a short design doc.
4. When the user says "remember this" or "don't suggest that again", record it in the Decisions section below.
5. Commit to git whenever the game is in a working state.

## Environment
- The user is on a Windows PC. Claude runs inside Anthropic's reference dev container (Docker), and its firewall only allows npm, GitHub, the Claude API and a few others.
- Permission prompts stay on. Ask before running commands.
- Start the dev server with `npm run dev`. It already runs `vite --host`, so the user can open http://localhost:5173 in their Windows browser.
- File-change alerts don't reliably reach the container from the Windows folder, so `vite.config.ts` uses polling (`server.watch.usePolling`). Keep it. If the browser ever shows stale code, restart the dev server.
- Keep LF line endings in `.devcontainer` files (enforced by `.gitattributes`).
- `.devcontainer/init-firewall.sh` uses `ipset add -exist` to fix a duplicate-IP startup error. This is the user's own fix. Don't revert it.

- Example (dev server must be running): `node tools/screenshot.mjs --out <scratchpad>/shots 'wait:1500' 'press:Equal*10' 'hold:KeyD:800' 'shot:fleet'`. Quote the steps, because the shell (zsh) treats `*` as a filename wildcard. Run it with no steps for a single screenshot. Steps also include `rclick` and `wheel:down`/`wheel:up`.
- Dev-only test keys help set up scenes: `=`/`-` add/remove ship, `]` add 16 ships, `T` add one ship of the next tier up (you move into it), `G` invincible, `K` destroy on-screen enemies, `X` end the run (to see the report), `L` gain a level, `J` get every skill, `I` drop 3 items of one random rarity next to you (enough to merge), `Y` drop the next Merge Module level next to you, `E` spawn an elite, `H` spawn a swarm wave, `V` spawn a fleet of enemy variants (explosive and energy take turns), `B` spawn a Leviathan (boss), `N` make it fire its beam now (if your flagship is in range), `C` make it ram, `P` make it let go of an energy ball, `Z` wound it (1/20 of its health: blood and parasites), `B` plays its whole entrance (Shift+B: straight in), `R` send reinforcements now, `F` switch formation method (Original / Fill, remembered), `O` switch elites on/off (remembered in that browser via localStorage, overrides `CONFIG.elite.enabled`), `U` cycle the rotation mode (Grid / Hi-res / RotSprite, shared with ShipArt's Rotation buttons, remembered). - Use it to check visual changes before handing them to the user. The browser has no graphics card, so it can't judge smoothness or performance. The user does that.

## Code layout
- `src/engine/`: the small homegrown engine (asset loading from the manifest, pixel renderer with whole-number zoom, sound playback (`sound.ts`), input, fixed 60 Hz game loop; `settings.ts` for remembered browser settings; on faster screens ships and shots are drawn between steps (`drawAtSmoothPositions` in `Game.ts`) to avoid a double-image stutter).
- **CRT screen effect (2026-11-17, the user's request from a reference image):** `src/engine/crt.ts` (`CrtFilter`, WebGL 2) draws the renderer's buffer onto its own canvas (`.crt-canvas`, laid over the game canvas, no pointer events) in `renderer.end()` when `renderer.crt.params.enabled`: glow (bright pass at ¼ size, blurred twice), colour fringes, curved glass (black corners), colour stripes from the image `ui.crt-mask` (tiled; brightness made up for), scanlines, vignette, lifted blacks, softness, grain, flicker, rolling band; sizes in pixels of a 1080-tall *window*. No WebGL 2 → plain drawing. With the look's `hud` on, `src/CrtOverlay.tsx` lays the stripes (multiply) and dark corners over the whole page as two top-level layers (`.crt-layer`; never wrap them: a wrapper stops the multiply and turns the stripes into a grey film) and gives text a fringed glow (`body.crt-hud` text-shadow); the shader then skips its own stripes and corners. The picture curves but the mouse doesn't. **Settings and presets (2026-11-17)** in `src/game/screenEffect.ts` (`screenEffect` store, `useScreenEffect`): on/off is personal (`fleet-game.screen-effect`); a *look* = every other setting incl. `hud`; presets saved in the browser (`fleet-game.screen-effect-presets`; per site address, so local presets never show on live); the **live default** = `public/assets/screen-effect.json` (loaded at start, `CONFIG.crt` if missing), written by "Designate as live default" (shown only in `npm run dev`, `CAN_DESIGNATE`; dev server `POST /__shipart/screen-effect` in shipart-plugin.ts); goes live when pushed. Players who never touch the sliders follow the live default (`own` null); a slider change makes their own copy until they load "Live default" again. The live file changes only on Designate; the preset it came from shows "LIVE · out of date" when edited since (the user's choice). Tabs of the site stay in sync (`storage` event). UI: `src/ScreenEffectPanel.tsx` (presets list with LIVE badge, Save as new, Update, Rename, Delete, Designate; HUD checkbox; sliders; styles in `screenEffectPanel.css`), in Settings → Screen effect (plus a one-click switch in General) and in **ShipArt** (toolbar: **CRT** = ShipArt's own preview switch `shipart.crt`, and **Screen effect…** = the panel in a draggable floating window, `src/shipart/ScreenEffectWindow.tsx`; the preview always draws its own stripes/corners (`hud: false`), and the handles layer stays crisp above). ### Game concept: pixel-art spaceship fleet combat
- The player starts as a single spaceship and grows a fleet. As the fleet grows, the camera zooms out and the fights get bigger, eventually fleet against fleet.
- **Movement:** the flagship is 20% faster moving toward where it faces (the cursor) and 18% slower backing away, blended smoothly (`directionalSpeed`). **Shift boost** (2.2× speed) runs on stamina (`CONFIG.boost`): 3 s from full, refills in 6 s after a 0.75 s rest; running dry locks it until 30% refilled. Boost time grows 1.5× per tier of the ship you fly (`durationPerTier`). The flagship's command ring is the stamina meter (a flipbook whose frames go empty → full, dimmed while locked). **Space dash:** the whole fleet is kicked to 8× speed at once, fading back over 0.5 s, with an 18 s cooldown. The extra speed scales with zoom (3/zoom) so the dash covers the same share of the screen at every zoom and a flipbook trail (`vfx.dash`) behind each ship (`CONFIG.dash`).
- **Touch screens (2026-11-15):** `IS_TOUCH_DEVICE` (engine/touch.ts: main pointer is a finger, or `?touch` in the address to test on a PC) shows `TouchControls.tsx`: thumbstick bottom left (2026-11-16: `min(375px, 75vh)` wide, 15vw from the left and 5vh up; knob reach a share of its size, `STICK_REACH`) (moves the ship and turns it to face where you push; `Game.readTouchControls` aims 300 px ahead of the ship in the last stick direction), Defend and Attack (big) with Dash and Boost (small) bottom right, a pause button top right; the keyboard help bar is hidden.
