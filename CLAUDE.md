- A simple browser game the user can play and keep improving.

## Code layout
- `src/engine/`: the small homegrown engine (asset loading from the manifest, pixel renderer with whole-number zoom, sound playback (`sound.ts`), input, fixed 60 Hz game loop; `settings.ts` for remembered browser settings; on faster screens ships and shots are drawn between steps (`drawAtSmoothPositions` in `Game.ts`) to avoid a double-image stutter).
- `src/game/config.ts`: every tuning number (speeds, health, waves, zoom steps, ship types and their hit sizes). Its comments also feed the public tuning page: give every new setting a one-line `/** */` description, and start a group of plain settings with a `// == Title: note ==` line.
- `tools/make-tuning-page.mjs`: runs at the end of `npm run build` and writes `dist/tuning.html`, a table of every setting with its value and description, read from `config.ts`. It's published at https://sdc-jpg.github.io/fleet-game/tuning.html (the user's teammate uses it) and linked in the Discord build post. It warns about settings with no description. Sections are grouped into collapsible categories (2026-11-16, the user's request): Art and audio, Weapons, Defensive skills, Passive skills (skills by their `side` in `SKILLS`), Difficulty (everything else), Other; the lists of config keys per group (`ART`, `WEAPONS`, `OTHER`) are in the tool.
- `src/game/save.ts`: saving and loading equipment (see Progression).
- `src/game/artLayout.ts`, `artKinds.ts`, `particles.ts`: art layouts from `public/assets/art.json` (ships and objects: base image per state, mounts = images and/or particle emitters per state with a VFX point, named points like a missile's impact point, particle defaults per mount category, image animation settings); the kinds ShipArt knows (ships; objects: missile) with their states and points; particles (`emitMounts`). `drawLayoutArt` in `render.ts` draws a ship or object with its layout (used by the game and ShipArt).
- **ShipArt tool** (`shipart.html`, `src/shipart/`): rollout menu on the left (Ships; Objects: Missile, Mine, Gun shot, Laser, Wreck, listed by tier; Effects) with a filter; preview states per kind (ships Idle/Move/Boost/Dash; missile Inert/Fired up/Impact/Sequence) with Fly, Spin, team colours, zoom, stars, rotation mode; place and drag mounts, their VFX points and named points (yellow); "+ Emitter" adds a particle-only mount; the view (object or effect, state per kind, tier, zoom, Fly/Spin/team/guides, selected mount, open sections) is remembered in the browser (`shipart.view`) and the mouse wheel over the preview changes zoom; Save writes `art.json`. The purple **VFX panel** holds the selected mount's effects: VFX point, particles per state (on/off, image, spawn rate, life, speed, drag, angle = spawn cone width, 360 = every direction), editing either this mount or the defaults for its category ("Make default for all <category>") (`particleDefaults`, moved out of `CONFIG.particles` at the user's request); "Apply to all <category> mounts" copies this mount's settings for the shown state to the defaults and clears every mount's own values of that category for that state (asks "Override settings for N mounts?" first, N = mounts of that category on in that state; on/off unchanged; undoable), a particle image preview, "Open image" and "Copy folder path". New VFX settings go in this panel. `/__shipart/info` gives the project's Windows path (read from the container's mounts at run time; never write it to a file, it contains the user's name). `tools/shipart-plugin.ts` (in `vite.config.ts`) gives the dev server `/__shipart/files` (lists art) and `/__shipart/save` (writes `art.json`), and writes `assets/art-files.json` into builds so the published copy (view-only) knows the art. Screenshot it with `--url http://localhost:5173/shipart.html`.
- **ShipArt plan (agreed 2026-11-13):** phase 1 objects + rollout (done: missile with flame mount, trail emitter, impact point); phase 2 Effects section (done: every `vfx.*` previewed in the viewport over stars with tier buttons; flipbook speed and loop, applied to all tiers by default or only this tier, saved to `manifest.json` through `/__shipart/manifest`, which rewrites only the changed entries' lines; mount images' flipbook (frames, speed, loop) also in the purple panel); phase 3 image source (done: per tier, pick another PNG with N frames side by side, or import a zip of PNG frames: `/__shipart/import-zip` unpacks them in name order into `vfx/<effect>/frame-01.png`..., all the same size, replacing an earlier import there; the entry switches to a `files` list on Save; the client waits until the dev server serves the new files); phase 4 more objects (done): mine (Armed; Blast point), gun shot (Flying; Hit point), laser (Warning, Beam; mounts at the muzzle, the beam is tiled `vfx.laser`), wreck (Drifting; own colours, shown on its marker). The game draws all of them through their layouts and emits their particles; effects at points use `Effect.at`.
- `src/game/skills.ts`, `progress.ts`, `curves.ts`: pilot skills; XP, levels and cards; progression formulas.
- `src/game/world.ts`: game rules (no drawing; it queues sound events in `state.sounds`, which `Game.ts` plays). `src/game/render.ts`: drawing. `src/game/Game.ts`: connects input, rules and drawing.
- `src/App.tsx`: React canvas and HUD.

## Decisions
<!-- Things the user asked to remember, or asked Claude not to suggest again. -->
- **Art must be easy to swap.** The user is a digital artist and will eventually replace all placeholder art with their own: images with transparency (alpha), flipbook (frame-by-frame) animations, VFX such as explosions, and characters. Build with this in mind from the start:
  - Draw everything visual from image or sprite assets. Don't hard-code shapes into game logic.
  - Keep art files in one clear folder, and list them in a single asset manifest (a file mapping names like `player.idle` or `vfx.explosion` to their files and frame settings).
  - Support flipbook animations from sprite sheets or numbered frame files, with frame size, frame count, frame rate and looping set in the manifest, not in code.
  - Don't let gameplay depend on the exact pixel size of the art. Use separate collision sizes and anchor points.
  - **Separate enemy ship art (2026-11-16, replaces "one image set for both teams"):** ships are drawn in their own colours, never recoloured: player `ship.fighter*`, enemy `ship.enemy*` (`SHIP_TYPES.*.sprites.enemyShip`; first made by `tools/make-enemy-ships.mjs` from the player art turned red, no overwrite without `--force`; own layouts in art.json, ShipArt lists Ships → Player / Enemy). `shipArtBase(s)` in render.ts picks the art by `s.hijackedFrom ?? s.team`, so a hijacked ship keeps its old art with a heart above it (`ui.hijack-heart`, recoloured to the side it fights for, `CONFIG.hijack.heartGap`). Wrecks: one grey image. **Guns (stage 2–3, 2026-11-16):** `ArtLayout.guns` (art.json, ShipArt's Guns section, `src/shipart/GunsPanel.tsx`; orange handles in the preview): position, angle, size (tier of shot), type (`WEAPON_TYPES`), turret, optional image (`parts/gun-*.png`, excluded from mount categories); none placed = `defaultGuns` (today's guns exactly). `src/game/guns.ts` `balanceGuns`: tier DPS budget split by size weight `powerPerTier^(size−1)`, interval `fireCooldown × fireIntervalPerTier^(size−1) × type rate`, × type efficiency (`CONFIG.guns`); `gunsOf(ship)` cached per design+tier (layouts given by `setGunLayouts` in Game.ts). world.ts `fireGuns` (modes player/ai/forward) replaced the old volley `fire`; per-gun `Ship.gunTimers` and turret angles `Ship.gunAim`; shots use the gun size's speed/reach/sprite (`shotStatsFor`). **Weapon types (stage 4):** energy = `fireEnergyGun` (beam in `state.beams`, hits every enemy in a line, `CONFIG.guns.types.energy` length/width), explosive = `fireExplosiveGun` (missile bullets flying by `CONFIG.missiles`, `types.explosive` missiles/spread, locked on the enemy nearest the aim point); kill sources "gun", "gun-energy", "gun-explosive" (`gunSource`). **Enemy variants (stage 5):** `Ship.variant` ('energy'/'explosive', `EnemyVariant`), art `ship.enemy-energy*` (purple) / `ship.enemy-explosive*` (orange) from `make-enemy-ships.mjs`, `sprites.enemyVariants`; their standard guns fire their type (`artWeapon`). Each wave: `CONFIG.variants` chance 0.3 that a third of the wave's non-elite ships (those nearest a random one, `addVariantSquadron` in updateWaves) are one variant (explosive from wave 7, energy from 12, toss-up when both; `rollVariant`). Elites never. Test key `V` spawns a variant fleet (alternating). **Shots, lasers, shields and other effects keep team recolouring** (sky blue parts, `CONFIG.teamColors`; `drawLayoutArt`/`teamSprite` take `team: null` for own colours). Plan: `docs/SHIP-GUNS-AND-VARIANTS.md`.
  - **Placeholders must stand out from the user's art.** Never imitate the user's art style when generating new assets. Keep the original placeholder style (simple flat-coloured shapes with a dark 1 px outline, like the first 32×32 fighters).
  - **Sounds follow the same rules:** sound effects only (no music for now), each in `public/assets/sfx/`, listed by name in the manifest's `"sounds"` section with volume and overlap limits, with `.t2`… tier versions falling back to a lower-pitched smaller tier. The recruit sound gets brighter with the wreck's tier (manifest `pitchPerTier`). Looping sounds (2026-11-16): `Sounds.setLoop(name, level, pitch)` fades a looping sound to a level each step (0 = fade out and stop); the ship you fly hums (`sfx.engine-move`) while moving and plays `sfx.engine-boost` instead while boosting (the user's choice 2026-11-16: a copy of the hum file, manifest volume 0.1 vs 0.08), deeper per tier, silent when paused or over (`Game.updateEngineSound`, levels `CONFIG.audio.engineMoveLevel`/`engineBoostLevel`); the short `sfx.boost` still plays when boost starts. Sound is on by default, M or the HUD button toggles it, and wingmen's shots play quieter (`CONFIG.audio.allyShotVolume`; may become silent if distracting).
  - **Ship parts are separate from the ship image (2026-11-13):** the base ship image stays the same in every state; thrusters (and later turrets etc.) are mounts placed with ShipArt. Part images live in `public/assets/parts/` named `<category>-…png` and are found automatically (no manifest entry). An animated part can also be a folder of frame PNGs (`parts/thruster-boost-3/…-001.png`, name order with numbers counted properly, same size); layouts refer to it as `parts/thruster-boost-3/` (trailing slash), and the game gets its frames from the art file list (`fetchArtFileList`). A mount has an image per state or none (hidden), so boost-only thrusters are possible. Dash doesn't change thrusters. The old `.move`/`.boost` ship images are no longer in the manifest.
  - **Rotation and laddering (comparison built 2026-11-13, choice pending):** rotating pixel art on the game-pixel grid makes laddering. `renderer.rotation` has three modes to compare: `grid` (original), `hires` (whole scene drawn at screen resolution, so art pixels tilt as solid squares; no help at 1× zoom, where T3+ are seen), `rotsprite` (`src/engine/rotsprite.ts`: Scale2x ×3 to 8×, rotated copy per angle step made on first use and kept; 128 steps; ships, their mounts and wrecks only, other sprites use grid). Default is grid until the user picks.
  - Placeholder art should follow the same conventions, so swapping in real art means replacing files (and maybe editing the manifest), not changing code.

### Game concept: pixel-art spaceship fleet combat
- The player starts as a single spaceship and grows a fleet. As the fleet grows, the camera zooms out and the fights get bigger, eventually fleet against fleet.
- **Movement:** the flagship is 20% faster moving toward where it faces (the cursor) and 18% slower backing away, blended smoothly (`directionalSpeed`). **Shift boost** (2.2× speed) runs on stamina (`CONFIG.boost`): 3 s from full, refills in 6 s after a 0.75 s rest; running dry locks it until 30% refilled. Boost time grows 1.5× per tier of the ship you fly (`durationPerTier`). The flagship's command ring is the stamina meter (a flipbook whose frames go empty → full, dimmed while locked). **Space dash:** the whole fleet is kicked to 8× speed at once, fading back over 0.5 s, with an 18 s cooldown. The extra speed scales with zoom (3/zoom) so the dash covers the same share of the screen at every zoom and a flipbook trail (`vfx.dash`) behind each ship (`CONFIG.dash`).
- **Touch screens (2026-11-15):** `IS_TOUCH_DEVICE` (engine/touch.ts: main pointer is a finger, or `?touch` in the address to test on a PC) shows `TouchControls.tsx`: thumbstick bottom left (2026-11-16: `min(375px, 75vh)` wide, 15vw from the left and 5vh up; knob reach a share of its size, `STICK_REACH`) (moves the ship and turns it to face where you push; `Game.readTouchControls` aims 300 px ahead of the ship in the last stick direction), Defend and Attack (big) with Dash and Boost (small) bottom right, a pause button top right; the keyboard help bar is hidden. Settings → "Left-handed controls" (touch devices only; `fleet-game.touch-left-handed`, `Game.setLeftHanded`, `hud.leftHanded`) mirrors the stick and buttons (`.left-handed` CSS; labels unchanged, pause stays top right). CSS placeholders (`.touch-*`), separate so art can replace them. The equipment screen still needs mouse dragging and right-click (tap works for buttons only).
- **Shots inherit speed (2026-11-15, `CONFIG.shotInherit`):** gun shots, merge bursts, Gatling bolts and the first Splitting Beam get the part of the firing ship's velocity along the shot (forward only; `inheritedSpeed` in world.ts), × `share` (1), capped at the ship's normal top speed (so boost and dash add nothing); their lifetime shrinks so reach stays the same. Both teams.
- **Auto-fire:** Q toggles it; it acts like holding left click (gun plus weapon skills).
- **Pause:** Esc toggles it. While stopped (pause, equipment, cards) the loop runs at 30 FPS. The game also pauses by itself when the window loses focus, and the screen isn't redrawn while paused.
- **The first kill of a run always leaves a wreck** (`firstKillWreck`). Wrecks show the yellow `ui.wreck-marker` brackets only before wave 10 (`wreckMarkerUntilWave`, 2026-11-16).
- **Flagship death (2026-11-15, `CONFIG.death`):** the ship you fly being destroyed (also when command passes on) gets `vfx.flagship-explosion` + `sfx.flagship-explosion`, a screen shake (`state.shake`, applied to the camera before `r.begin`) and spinning debris (`state.debris`, frames of `vfx.debris`, team-recoloured, keeping the ship's velocity × `debrisMomentum` plus an outward burst; `flagshipExplosion`/`updateDebris` in world.ts). After the last ship dies the world keeps running for `screenDelay` 1 s (no waves, no survival time) before the end-of-run screen (`Game.endShown`). The blow that destroys your **last** ship first holds it (`state.finalBlow`; it stays in the fleet, dead, until `ready`): Game.ts runs time at `slowmoScale` 8% for `slowmoTime` 0.8 real seconds (`Game.timeScale`, particles too) and zooms in ×`slowmoZoom` 1.4 (`setZoom(..., unrounded)`, the one place zoom isn't a whole pixel step), then it explodes and the zoom eases back. Debris is slow and space-like (burst 15–70, drag 0.08, spin 3, life 3–5 s).
- **End-of-run report:** ships destroyed and lost (count and value; merged ships aren't losses), and a graph of fleet value with one point per wave start (as wide as the panel; faint line every 100 value, or a bigger round step past 20 lines; tick every 5th wave, labelled only near 25/50/75% of the run, rounded down to multiples of 5).
- **Run log** (teammate's request, `src/game/runLog.ts`, `src/RunLog.tsx`): every finished run in this browser is kept (localStorage `fleet-game.runs`, all versions, max 1000): version in gray, player code (two random letters per browser, `fleet-game.player`; may become a nickname; runs from before codes count as this browser's), end date/time, Gearscore ("–" on older runs), best value, time, waves reached, destroyed, lost, value destroyed, value lost, each on a dark red bar scaled to its column's best (the best bar is orange). Views: "My runs" (newest first) and "Leaderboard" (every player's runs, best value first; other players' rows gray). Runs are only in this browser for now, so other players' runs need a shared store (not built yet). Flush right, full height, on the game-over screen; the report panel moves left of it.
- **Edge markers (2026-11-15):** off-screen ships and wrecks get arrows at the edge; loot gets a rarity-coloured dot (`ui.dot.loot.<rarity>`, `merge-module` for Merge Module drops) on a ring further in, `CONFIG.edgeMarkers.lootDotGap` past the biggest arrow, so they never overlap.
- **Browser behaviour (2026-11-15):** `main.tsx` blocks the right-click menu, text selection and image dragging on the whole game page (text boxes excepted); `CrashScreen.tsx` shows the error (copyable) instead of a black page if React drawing fails. Saved equipment is written as soon as it changes (`saveIfChanged`).
- **Resume interrupted run (2026-11-15, `src/game/runSave.ts`):** a small snapshot (wave, fleet value, level/XP/pending levels, skills, card bonuses, stats, graph) goes to localStorage `fleet-game.run` every `CONFIG.runSave.every` s, at each new wave and on page hide/close; deleted at game over or "New run". On opening, "Resume your last run?" waits (game frozen): resuming clears the field, rebuilds the fleet from its value (`rebuildPlayerFleet`, tierCounts) and replays the saved wave from its start (the user chose this over an exact restore).
- **Statistics (2026-11-15, preparing a statistics tab in the Log):** `RunStats` (world.ts, `emptyStats` fills missing fields) also counts items collected, merges, kills per tier (`killsByTier`), per enemy class (`killsByClass`: elite/swarm/fleet/lone, `enemyClass` in world.ts; new enemy kinds go there), per weapon (`killsBySource`: kills + value; every `damageShip` call and shot carries a source: "gun", "merge", "hijack" or a skill id; the killing blow's source is `Ship.killedBy`) and skill uses (`skillUses`, your skills only). Each run log entry stores them; `src/game/lifetime.ts` adds every finished run to lifetime totals (localStorage `fleet-game.lifetime`, wiped by Clear saved progress), shown in the pause screen's **Lifetime** tab (`src/LifetimeStats.tsx`, 2026-11-16: totals plus the KillChart). The defeat screen shows items collected · merges and the "Destroyed by" chart (`KillChart.tsx`: one column of bars, biggest full, Kills / Fleet value toggle).
- **Version stamp** bottom right: build date (`__BUILD_TIME__`, set in `vite.config.ts`, shown in the viewer's time zone) and version, e.g. "2026/11/13 v20" ("dev" locally).
- **Early waves:** waves 1–10 bring three times as many lone enemies (`earlyWaveExtraEnemies` 2 = +200%, since 2026-11-16; was 0.3), still capped by `maxLoneEnemiesPerWave`.
- **Swarm waves (2026-11-14, `CONFIG.swarm`):** when an elite is due, 25% of the time a swarm comes instead (also with elites off). 30 + 0.25 × wave ships (max 60), tiers at least 3 below your biggest ship this run (never below T1; 40% one tier smaller still), in chevrons of about 10 (2–3 nested V rows) spread over a 120° arc. Each chevron (`Fleet.swarm`) flies off a straight line to you by 55° far away down to 20° up close, all turning the same way, so they curve in and swirl around. "Swarm incoming!" banner and `sfx.swarm` klaxon.
- **Gearscore:** sum of the rarity tiers (1–7) of equipped items (`gearscore` in `equipment.ts`), shown under Fleet bonuses, saved with the equipment and in each run log entry.
- **Reinforcements (2026-11-16, `CONFIG.reinforcements`, "Reinforcements" section in world.ts):** past wave `afterWave` 30, when your fleet value drops below `belowShare` 0.7 × your best this run (`maxFleetSize`), Fleet HQ sends a friendly fleet worth `waveFleetValue(wave)` (`maybeSendReinforcements` → `sendReinforcements`): green banner "Fleet HQ is warping in reinforcements!" (`hud.reinforcementAlert`, `.reinforce-toast`) and `sfx.reinforcements`; it warps in (`vfx.warp-in`) just out of view behind you and dashes (eased, dash trail) to `aheadDistance` 300 ahead along your movement, in formation; then flies to your flagship at `joinSpeed` (`aimAndShoot` on the way) and joins your fleet when touching any of your ships (like a wreck). `Ship.reinforcement` (phase dash/join), `Ship.immune` (Infinity on the way, `shieldAfterJoin` 0.5 s after joining; `damageShip` ignores damage, Hijack can't take them, drawn with the shield bubble); fleets in flight in `state.reinforcementFleets`. `perRun` 1 (`state.reinforcementsUsed`, kept in the run save) and a hidden `cooldown` 300 s of play between them (`lastReinforcementAt`). Test key `R`.
- **Commander view (2026-11-16, teammate's mockup, `docs/COMMANDER-VIEW.md`, `CONFIG.commander`):** when your biggest ship *now* is ≥ T4 (`fromTier`), only the top 3 tiers (`realTiers`) are ships; smaller ships of both sides (relative to your biggest; never elites) are HUD symbols `ui.hud.<side>.t<tier>` (`symbolTierMax`/`drawnAsSymbol` in world.ts, `symbolSprite` in render.ts; also ships smaller than T1 after detail steps). Symbol ships: fading targeting lines to `Ship.target` (set in `aimAndShoot`), shots/missiles drawn as `projectile.hud` (ShipArt object "HUD shot", `HUD_SHOT_KIND`), beams as thin lines, wrecks as `ui.hud.wreck`, no thruster particles. Settings → General: "targeting lines" and "show symbol ships' shots" (`Game.setCommanderLines/Shots`, remembered, defaults from config). Background (`drawBackground`, `Game.viewOptions`): black base, stars dimmed (`starDim`), blue shift + haze while on (fades over `fadeTime`); during Time Dilation red shift + haze + long-exposure smear (`CONFIG.timeDilation.redShift`, `smearCopies`, `smearSeconds`), replacing the old CSS edge glow. The art-swap rules apply (all placeholders).
- **Wave timer (2026-11-16):** top middle, under the help bar (`.top-stack` in App.tsx): "Wave N", a 2 px bar as wide as the XP bar filling until the next wave (`state.waveLength`), and initials for what the next wave brings: F fleet, E elite, S swarm (`wavePlan(state, wave)` in world.ts, also used to spawn waves; the elite-or-swarm choice is rolled one wave ahead in `state.nextSwarm`, so the letters are always right).
